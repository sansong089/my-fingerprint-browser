# 悬浮工具栏顶部停靠收起方案

本文记录悬浮工具栏顶部停靠、展开、收起的当前方案，以及多次迭代中已经踩过的坑。后续修改 `electron/main/index.ts` 中的工具栏逻辑时，应优先遵守这里的状态边界。

## 目标行为

- 工具栏默认以完整形态显示，尺寸保持 `590 x 50`。
- 工具栏靠近屏幕上边缘后，鼠标离开工具栏范围时收起为顶部细条。
- 鼠标进入顶部细条时，工具栏立即展开，并恢复完整样式和尺寸。
- 展开后如果仍靠近上边缘，鼠标离开完整工具栏范围就再次收起。
- 展开后如果被拖离上边缘，松开后保持完整悬浮，不再自动缩回。
- 收起条保持工具栏同色，使用圆角和轻微 3D 阴影，当前高度为完整收起高度的一半。

## 状态机

工具栏由主进程维护三个运行态：

| 状态 | 含义 | 持久化 |
|------|------|--------|
| `floating` | 完整悬浮工具栏，未停靠 | 保存自由位置 `x/y/displayId`，`collapsed=false` |
| `collapsedTop` | 顶部收起细条 | 保存顶部 `offset/displayId`，`collapsed=true` |
| `expandedTop` | 从顶部细条展开后的完整工具栏 | 不作为独立持久化状态，仍保存顶部停靠数据 |

核心转换规则：

- `collapsedTop` + 鼠标进入细条 -> `expandedTop`
- `expandedTop` + 鼠标离开完整工具栏 + 仍靠近上边缘 -> `collapsedTop`
- `expandedTop` + 拖离上边缘并松开 -> `floating`
- `floating` + 拖到上边缘附近并松开 -> `expandedTop`，随后鼠标离开时收起为 `collapsedTop`

## 实现原则

- 主进程是唯一状态源，负责窗口几何、拖动完成判定、收起判定和 `electron-store` 持久化。
- renderer 只发送“鼠标进入收起条，请展开”的 IPC，不负责判断何时收起。
- 收起判定使用 `screen.getCursorScreenPoint()` 读取真实鼠标屏幕坐标，再与当前 `BrowserWindow.getBounds()` 比较。
- 鼠标坐标监视器只在完整展开且需要判断离开时启用，进入 `collapsedTop`、窗口关闭或拖动开始时停止。
- 顶部判定使用当前显示器 `workArea.y` 和统一阈值，避免多显示器时按主屏误判。
- 程序性 `setBounds` 必须受 `suppressFloatingToolbarMove` 保护，避免主进程自己的调整触发拖动状态转换。

## 已知坑

- 不要依赖透明 frameless `BrowserWindow` 的 `mouseleave` / `pointerleave` 来收起。窗口高度从细条切回完整工具栏时，这类 renderer 事件容易丢失，导致“不会收起”或“展开后卡住”。
- 不要用固定延迟作为状态门槛。快速划过细条或快速拖动时，`setTimeout` 式等待会制造竞态，表现为偶发不能展开或不能收起。
- 不要把 `expandedTop` 当成持久化状态。它只是顶部停靠的临时展开形态，重启后应按 `collapsedTop` 或 `floating` 恢复。
- 不要让收起细条使用 `-webkit-app-region: drag`。细条需要可靠接收 hover/mousemove 以触发展开；拖离顶端应在展开后的完整工具栏上完成。
- 不要在工具栏远离上边缘后继续自动收起。自动收起只发生在“鼠标离开 + 工具栏靠近上边缘”这两个条件同时成立时。
- 不要清理无关 `setTimeout`。主进程中窗口排列、网络请求等其他计时逻辑与工具栏收起无关。

## 验收清单

- 拖到上边缘附近，鼠标离开后收起。
- 快速掠过顶部细条也能展开。
- 展开后鼠标离开，如果仍靠近上边缘则收起。
- 展开后拖离上边缘并松开，保持完整悬浮。
- 沿上边缘横向拖动后，停靠位置能保存。
- 多显示器下按工具栏所在显示器的工作区上边缘判断。
- `npx vue-tsc --noEmit` 通过。
- `npx vite build` 通过。
